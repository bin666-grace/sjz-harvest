Architecture Design · v0.1.0

特勤处收菜 · 架构设计文档

三角洲行动手游（com.tencent.tmgp.dfm）特勤处 「收菜 → 补产 → 等待下一轮」外部 UI 自动化。基于无障碍截屏 + ML Kit 中文 OCR + 手势注入， 不读写内存、不修改封包、不注入进程。本文是实现的完整架构契约。

01定位与边界

本项目是一个运行在 Android 设备上的「UI 宏」：它看到玩家能看到的界面，执行玩家能执行的点击， 并按玩家设定的生产计划循环。它不触碰游戏内部状态。

它做什么

  • 截屏 + OCR 识别特勤处总览
  • 识别四个部门的空闲 / 制造中 / 已完成
  • 点开部门收取成品，按计划补充制造
  • 计算剩余时间，定时唤醒下一轮

它怎么做

  • AccessibilityService 截屏（API 30+）
  • ML Kit 中文 OCR（离线 bundled）
  • 文字锚点优先，固定坐标为兜底
  • root shell / 无障碍手势 / dry-run 三种输入

它不做什么

  • 不读游戏内存、不注解进程
  • 不修改网络包、不伪造服务器请求
  • 不做反检测 / 反作弊规避
  • 不自动登录、出售、跑刀、对局、多开
合规提示

即使只做 UI 自动化，仍可能违反游戏用户协议并触发行为检测，存在封号风险。 本项目不承诺账号安全，也不提供任何规避手段。使用风险自负。

02目标与非目标

设计目标

  • 安全第一：任何不确定状态停止，不盲点；所有动作可审计。
  • 鲁棒感知：OCR 文字锚点优先，兼容分辨率、刘海与模拟器差异。
  • 可测试：业务核心纯 Kotlin，不依赖 Android API，可 JVM 单测。
  • 可恢复：断点续跑，失败不消耗计划次数，页面异常可回总览。
  • 可离线：不联网、不上传截图，配置与日志都在应用私有目录。

v0.1 非目标

  • 自动登录、自动出售、自动跑刀、自动对局、多开。
  • 内存读写、封包修改、进程注入、反检测/反作弊规避。
  • iOS 客户端；PC 版为第二优先级（pc/ 目前仅接口骨架）。
  • 自动买材料默认关闭；手游交易行流程验证后再评估。
  • 无签名 release 渠道、应用商店分发。

03实机事实与业务闭环

以下 UI 事实已在 Redmi 2312DRA50C（HyperOS V816，横屏 2712×1220）上确认， 与 PC 端参考实现（DeltaForceSS）的交互模型差异很大。

已确认的界面元素

  • 总览四卡片：技术中心 / 防具台 / 工作台 / 制药台，位置固定。
  • 制造完成的卡片没有「完成/收取」文字，只有物品图 + 右上角黄色「!」角标。
  • 点击部门标题进入的是「XX升级」页，不是物品列表。
  • 「XX升级」页点「前往生产」才进入「左列表 + 右详情」生产页。
  • 生产页收取按钮文字为「收获」。
  • 材料不足时底部按钮显示「一键补齐」。
  • 生产页/升级页不响应安卓返回键；左上角页面内箭头可逐级返回，生产页需连点两次。
  • 仓库满时点「收获」只弹「仓库空间不足」toast，按钮仍在、物品不入账。

由此产生的三个关键适配

  • 角标判定：OCR 判不出 DONE，改用像素颜色 + 连通域检测黄色「!」。
  • 固定分区轮巡：不依赖状态文字，直接按固定顺序点开四个部门看有没有可收物品。
  • 两级导航：部门标题 →「前往生产」→ 列表；收取按钮是「收获」。

对应 ADR：D033、D034、D035、D037。

业务闭环

1
前台校验
读取前台包名，必须为 com.tencent.tmgp.dfm；否则本轮中止（不终止会话）。
2
截屏 + 全屏 OCR
AccessibilityService 截图 → ML Kit 中文识别 → 文字与包围盒；判页并定位四个部门标题。
3
状态判定
状态文字只归属给位于其上方的标题锚点（防串行）；黄色角标 → DONE。
  • 空闲中 → IDLE
  • HH:MM:SS → CRAFTING(remainingSec)
  • 收取 / 领取 / 完成 → DONE
  • 无状态文字 → UNKNOWN（绝不当作 DONE）
4
轮巡收取（sweepDepartments，默认开启）
按 技术中心 → 防具台 → 工作台 → 制药台 依次点进部门：
  • 页面上有 收取/领取/收获 → 直接点；
  • 是「XX升级」页 → 前往生产 → 生产页点「收获」；
  • 没有可收物品 → 返回总览；制造中的部门跳过。
轮巡收不到不算失败、不进入冷却。
5
按计划补产
部门空闲且有计划 → 进入生产列表 → 左侧视口模糊匹配目标物品 → 点击 → 校验右侧详情标题 → 开始制造 → 验证按钮消失 → 返回总览。
材料不足：默认放弃；开启 autoBuyMaterials 后才走补料确认流程。
6
计算下次唤醒
重新观察状态，取最小剩余时间 + 30s 缓冲；有可收/可造物品则立即进入下一轮。

04系统上下文

所有进出都发生在 Android 框架层：App 只能看到屏幕像素与前台包名，只能发出触摸手势。 没有网络链路，也没有跨进程内存访问。

06运行时模型

进程与服务

组件职责关键点
SjzAccessibilityService 系统绑定的无障碍服务，常驻 暴露 instance: StateFlow；提供 takeScreenshot()、dispatchGesture()、foregroundPackage()
AutomationForegroundService 会话期间的 specialUse 前台服务 防止 MIUI / HyperOS 冻结后台进程；与 Controller 共用通知 ID
AutomationController 单例状态机与协程调度 start/pause/resume/stop；StateFlow<AutomationUiState>；每轮调用 HarvestFlow.runCycle()
ControlReceiver 通知栏动作广播 暂停 / 继续 / 停止，无需悬浮窗权限
MainActivity 前台界面 绑定状态流；退到后台不影响自动化

线程与协程

  • 截屏、OCR、root 命令走 Dispatchers.IO；业务循环单线程顺序执行，不做并发点击。
  • takeScreenshot / dispatchGesture 回调在主线程，包装为 suspendCancellableCoroutine。
  • ML Kit recognizer 非线程安全，用 Mutex 串行化。
  • 截屏串行且最小间隔 400ms，避开系统 ERROR_TAKE_SCREENSHOT_INTERVAL_TIME_SHORT（约 333ms）。
  • 暂停用 CompletableDeferred / Mutex 阻塞在轮次之间；停止用 Job.cancel() + 标志位。

生命周期

用户点开始
  → 检查无障碍服务已连接（否则提示去系统设置）
  → 加载配置（app / profile / catalog / plan）
  → 选择输入后端（auto: root → accessibility → 报错）
  → 启动前台服务，通知栏显示「运行中」
  → loop:
       检查暂停 / 停止 / 安全限制 / 前台包名
       flow.runCycle()
       记录 nextWakeAt
       delay(nextWakeSec)
  → 停止：取消协程、回收 OCR、停止前台服务、更新通知

无障碍服务被系统关闭时，Controller 监听 instance == null，停止循环并提示用户。

07状态机

7.1 自动化状态机

状态字段：running、paused、phase、lastMessage、 nextWakeAtMs、cycleCount、lastObservation。

7.2 页面判定

输入全屏 OCR 文字与包围盒，按以下顺序判定（顺序本身是契约）：

1
制造面板
命中「开始制造」等具体按钮，或材料锚点相似度 ≥90
2
交易行
至少 2 个交易行锚点（交易行 + 最低价）
3
总览
≥2 个部门标题；单标题需邻域出现状态词/计时器
4
部门页
文字元素 ≥6 且不满足以上条件
5
未知
UNKNOWN → 禁止点击
为什么顺序重要

制造面板里也可能出现「制造」二字，所以先用更具体的「开始制造」/材料锚点； 详情页通常只有一个部门标题，单标题不能直接判总览，否则补产会停在详情页而不是进入列表。 主界面底部导航含「交易行」三字，单锚点会把大厅误判成交易行，因此要求 ≥2 锚点。

7.3 部门状态解析

集中在纯 Kotlin 的 DashboardStatusResolver，可在 JVM 单测：

  1. 四个部门标题作为锚点；漏识别时先按 2×2 卡片网格（同行/同列已知标题）推断，仍失败才用 departmentAnchorPoints 归一化兜底。
  2. 每个 OCR 元素只归属最近的部门锚点，并限制在 statusSearchRadiusPx × widthFactor 半径内。
  3. 关键约束：状态文字只归属给位于文字上方的标题；上方无锚点才退回全局最近锚点。
  4. 状态优先级：idleKeywords → IDLE；计时器正则 → CRAFTING(剩余秒)；craftingKeywords → CRAFTING；doneKeywords → DONE；其余 UNKNOWN。
  5. 黄色角标由 AlertBadgeDetector 检测，并按「标题右侧 dx/dy 窗口」归属部门。
为什么状态只归属上方标题

2712×1220 上排卡片的「空闲中」在垂直方向上反而更靠近下排标题； 按最近锚点会把技术中心的状态串给制药台（实机 dry-run 曾出现）。修复后通过实机验证。

为什么角标不能用最近锚点

完成角标常更靠近相邻卡片的标题；必须用「标题右上方窗口」筛选。 左侧升级栏的角标 dx<0，右侧设施列表的角标 dx 过大，均被排除。

7.4 业务周期

runCycle():
  obs = observer.observe()          // GameNotForeground → 本轮中止，不终止会话
  if obs.page != DASHBOARD:
      tryRecoverToDashboard()       // 最多 2 次；主界面点「特勤处」，不盲按返回

  order = if (sweep) sweepOrder() else Dept.entries
  for dept in order:
      status = obs.status(dept)
      sweepCollect = sweep && status.state != CRAFTING
      if status.state == DONE or sweepCollect:
          crafter.collect(dept)     // 轮巡失败不冷却；DONE 失败进入冷却
          refresh dashboard         // 收菜后必须重新观察状态
      if status.state == IDLE and plan.hasNext(dept):
          outcome = crafter.craft(dept, plan.next(dept))
          if outcome == SUCCESS: plan.consume(dept); persist()

  obs2 = observer.observe()
  next = Scheduler.nextWakeSec(obs2, plan, buffer)
  return CycleResult(...)
  • 收菜与补产可能连续发生；收菜后重新判空闲，不能沿用旧状态。
  • 单部门失败不阻塞其他部门；页面异常 / 前台异常立即中止整轮。
  • 失败部门进入 failureBackoffSec（默认 300s）冷却；仅冷却导致无唤醒时，推迟到冷却结束。
  • craft 必须确认制造面板已关闭才算 SUCCESS；只有 SUCCESS 消费计划。
  • 整轮未知或四部门全 UNKNOWN 累计到 maxConsecutiveUnknownCycles（默认 3）停止。
  • 每轮动作数超过 maxActionsPerCycle（默认 80）→ SafetyLimitReached。

08感知管线

从一块屏幕像素到「四个部门各是什么状态」，全部是可替换接口 + 纯函数。

01

02

黄色「!」像素采样 + 连通域

DeptStatus(tech/work/medical/armor)

像素角标检测

AlertBadgeDetector 是完全的纯 Kotlin 实现，输入 IntArray 像素与尺寸，不依赖 Android：

  • 目标颜色 RGB(244, 207, 103)，容差 28；卡片金色描边约 (200,168,80)，不会命中。
  • 步长 2px 采样，单个色块至少 16 个命中；外接框最大 80px，过滤大片金色图片/描边。
  • 按「标题锚点右侧 dx ∈ [90, 320]、垂直偏移 ≤ 180」窗口归属部门（基准 1920，按宽度缩放）。

OCR 与文本解析

MlKitOcrEngine

  • bundled 中文模型，离线、不依赖 Google Play 服务。
  • 宽度 <1600 时 2× 放大提升小字识别；坐标除以放大倍数还原。
  • 串行 Mutex；失败重试 ocrRetries 次后返回空结果并记录。

TextParser（纯 Kotlin）

  • parseTimer / parsePrice / isIdle / isDone
  • normalize：去空白标点，应用 OCR 纠错（如 番→盔）
  • similarity：归一化 Levenshtein 比率 0..100
  • bestMatch：按部门阈值返回最佳物品候选

09核心业务模块

9.1 轮巡收取（sweepDepartments）

HarvestFlow 在每轮开头读取 profile.dashboard.sweepOrder， 默认顺序 技术中心 → 防具台 → 工作台 → 制药台。对每个部门：

  • 状态为 CRAFTING 时跳过（一定没有可收物品）。
  • 否则点开部门，执行 CraftingController.collect(dept)：
    1. 当前页找「收取 / 领取 / 收获」→ 点击；
    2. 是「XX升级」页 → 点「前往生产」→ 生产页找「收获」→ 点击；
    3. 都没有 → 返回总览。
  • 收不到物品不算失败、不进入冷却；只有状态判定为 DONE 且收取失败才记失败。
  • 总览标题漏识别时，仅在 Page.DASHBOARD 页使用 departmentAnchorPoints 固定点进入。
为什么默认开启

实机完成卡片只有角标、没有文字，OCR 漏检或颜色偏差都会让状态停在 UNKNOWN。 固定分区轮巡是有界操作（每轮最多 4 次），点的是实机标定过的卡片位置，比纯状态识别更可靠。

9.2 补产与列表扫描

1
进入生产页
点部门标题 → 等待 → 若是「XX升级」页则点「前往生产」→ 确认进入「左列表 + 右详情」。
2
点击列表第一行（默认）
玩家把目标物品置顶后，直接点归一化固定点 itemList.firstRowPoint（0.17/0.239）；不按物品名扫描、不滚动。旧模式（firstRowSelect=false）才在 itemList.viewport 内做模糊匹配。
3
OCR 预审
第一行模式不依赖 OCR 选择物品；点完后读右侧 detailRegion 标题：读到且不是计划物品 → 中止；读不到 → 告警但继续。旧扫描模式仍用「首行不变」判到底。
4
校验详情
详情标题匹配目标才允许点「开始制造」；不匹配则停止，绝不误造上一件。
5
材料与开始制造
看到「一键补齐」= 材料不足（默认返回 MISSING_MATERIALS）；否则找「开始制造」并点击。
6
验证成功
等待后确认「开始制造」按钮消失 / 面板关闭；只有确认关闭才返回 SUCCESS 并消费计划。

各物品相似度阈值：tech 71 / work 96 / medical 80 / armor 80（来自实机 OCR 调参，见 DeltaForceSS 参考）。

9.3 补料流程（可选，默认关闭）

移植自 DeltaForceSS 的补料确认逻辑，但加了更严格的手游安全检查。 仅在 safety.autoBuyMaterials=true 时执行；默认配置下永不点击「一键补齐」。

if (findFillButton(snap) != null) {
    if (!safety.autoBuyMaterials) return CraftOutcome.MISSING_MATERIALS

    tap(fillButton)
    if (page == AUCTION) buyMaterials()          // 交易行路径，同样受单价限制
    else {
        // 必须同时识别到价格 + 确认按钮，且单价 ≤ auction.maxUnitPrice
        if (findAnyPrice(snap) == null) return MISSING_MATERIALS
        if (price > auction.maxUnitPrice && maxUnitPrice > 0) return MISSING_MATERIALS
        tap(findFillConfirmButton(snap))
        finishAfterFill()                        // 补齐后仍缺 → 放弃
    }
}

价格守卫

识别到价格且不超过 maxUnitPrice 才确认；0 表示不限。

按钮守卫

确认按钮必须与补齐按钮不同位置、不同文字，模糊阈值 90。

结果守卫

补料后必须看到制造面板且无补齐按钮，才继续「开始制造」。

尚未实机验证

手游补料确认页的真实布局与按钮文字尚未在设备上走通；因此默认保持关闭。 开启前请先手动确认交易行单价与确认页结构。

11错误处理与重试

异常处理
AccessibilityServiceUnavailable提示去系统设置开启，不重试。
CaptureFailed（全黑）重试 2 次 → 停止，提示 FLAG_SECURE / 窗口问题。
CaptureFailed（其他）按 capture.retries 重试 → 停止。
PageNotRecognized先尝试恢复总览（主界面点「特勤处」，不盲按返回）；仍失败停止并通知。
GameNotForeground中止本轮并等待最多 10 分钟；超时停止。不终止会话。
InputUnavailableauto 模式切换后端一次；仍失败停止。
ITEM_NOT_FOUND记录日志，跳过该部门，继续其他部门。
MISSING_MATERIALS / BUY_FAILED记录日志，跳过该部门；不扣计划次数。
连续 3 轮 OCR 全空停止（可能黑屏或被保护）。
SafetyLimitReached正常停止并通知。
未知异常记录堆栈 + 失败截图，停止。

重试原则：只有幂等的截屏 / OCR 可以重试；点击后不盲目重试，先重新观察页面。

12安全设计

默认安全策略

  • 前台包名校验：每次截屏/点击前确认仍在游戏内。
  • 页面确认：未知页禁止点击。
  • 每轮动作上限 80；可配置最大循环 / 最长运行。
  • 自动买材料默认关闭，开启需设置页二次确认。
  • dry-run：完整识别与决策，只记录不点击。
  • 暂停 / 停止：通知栏常驻，停止立即取消协程。
  • 日志脱敏：不记录账号 / UID；截图只存应用私有目录。

点击前的三道门

  1. 我们在游戏里吗？ 前台包名 == com.tencent.tmgp.dfm。
  2. 我们在哪个页面？ 页面判定明确，非 UNKNOWN。
  3. 目标真的在这吗？ 按钮/物品由 OCR 包围盒定位，点击点来自文字本身。

任何一道不满足 → 记录并停止/跳过，绝不“凭感觉”点。

设备侧保活（MIUI / HyperOS）

Game Turbo / PowerKeeper 会冻结后台进程，前台服务也不能豁免。需要把包名加入 MILLET_NO_RESTRICT_APP 白名单。另：am force-stop 会把无障碍服务从 enabled_accessibility_services 移除，需要到系统设置里重新开关，必要时重启设备。
